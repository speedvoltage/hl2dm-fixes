HUD editor
The original game HUD is selected with the Default preset. Choosing Classic,
Compact or Minimal enables customization. There is no separate enable button.
Open Options > HUD Editor, or bind hud_editor in Keyboard / Mouse.
Drag elements and their corner handles. Layout has position, size and one-click
horizontal/vertical centering. Appearance has a color picker (hue, saturation,
brightness, palette swatches and hex input), opacity and eight font choices.
The crosshair always stays centered: it has appearance controls and a size handle,
but no position controls or dragging. Old saved crosshair offsets are ignored.
Relevant elements also offer labels, values, bars and crosshair controls.
Chat, votes and crosshair have no visibility switches in the HUD editor; old
layouts cannot hide them. Crosshair enable and HUD Quick Info are in Game options.
Five custom slots are saved locally with the separate slot selector. Picking a
preset previews it immediately. Apply writes cfg/hud_layout.res; Cancel restores
the opening layout and HUD selection. Saved slots remain saved after Cancel.
User layouts and presets are excluded from release packages.
Preview zoom offers Fit and 75-400%. Use the wheel over the canvas or +/- keys
(including the numpad); right-drag pans the zoomed view. Nearby edges and centers
snap within seven canvas pixels, with cyan guides. Hold Alt to bypass snapping.
Ctrl+Z / Ctrl+Y and toolbar buttons undo/redo up to 64 edits in the current editor
session. Dragging and slider gestures are grouped. View navigation is not an edit.
The Help box contains the controls previously displayed below the canvas.
Crosshair Appearance has a 16-shape gallery. All weapons is the shared default;
each of the twelve weapons can override shape, color, opacity, size, gap, length,
thickness, outline and dot. Disable a weapon override to inherit shared settings.
Version-1 layouts load unchanged; version-2 layouts/presets save the overrides.
Killfeed samples use the in-game death-notice renderer and weapon/skull icons.
Headshots have a separate head/impact icon. Wings indicate that the attacker was
airborne at the time of the kill (walking movement, no ground entity, not swimming).
Both icons can appear together. Suicides and world deaths do not get these badges.
Vote Preview opens the real vote panel with your own name and sample counts.
Yes/No keys simulate a local choice; no request or ballot is sent to the server.
Restart / Pass / Fail preview both outcomes without kicking or banning anyone.
Close it with Escape or X to keep editing. With developer 1, cl_vote_preview
[self|pass|fail|close] and the scoreboard's Test self-kick entry do the same.
The vote panel has a kick/result icon, yes/no badges and the actual bound keys.
Distinct yes/no sounds accompany ballots; passed/failed sounds accompany results.
Counts briefly highlight when updated, and results pulse once. The existing vote
sound/animation options control this feedback.
HPH (https://gamebanana.com/mods/345189) was used as a design reference only.

Damage numbers
Options > Game offers hitmarkers on/off, eight fonts and a color palette with hex
input. One animated preview shows the draft font and color together. Apply saves;
Discard restores the previous settings. The circled information button explains
the server restriction and works with mouse hover or keyboard focus.
cl_hitmarkers controls the local preference. sv_hitmarkers remains authoritative.
Turning hitmarkers off hides the font/color controls without resetting their
pending values. Turning them on again restores those drafts. Apply includes the
hidden values; leaving Options uses the usual save/discard confirmation.
cl_hitmarker_font: 0 = Half-Life 2, 1 = GorDIN, 2 = GorDIN Bold, 3 = Tahoma,
4 = TF2, 5 = TF2 Build, 6 = TF2 Secondary, 7 = TF2 Professor. TF2 font files
and their attribution are included in resource/fonts; no system install is needed.
cl_hitmarker_color: RGB string, default "255 0 0".
Hitmarkers and bright models have information icons. While a connected server
disallows either feature, its row has a red tint, warning triangle and wrapped
explanation. The local preference stays editable but cannot override the server.
The warning updates when server policy changes and clears on disconnect.

Community server controls
Apply Changes beside Game mode switches DM/TDM without loading the map again.
It restarts the round: scores and timer reset, all active players respawn, and
entering TDM balances the teams. Spectators stay spectators. Console changes to
mp_teamplay use the same restart; matchmaking retains its assigned mode.
Bright player colors opens three color palettes for server admins. The replicated
cvars can also be placed in server.cfg:
sv_bright_models_dm_color "0 255 0"
sv_bright_models_rebels_color "255 0 0"
sv_bright_models_combine_color "50 150 255"
Only clients opting into bright models on community servers use these colors.
sv_bright_models 0 disables bright models on the server; the default is 1.
This also disables the teammate/enemy footstep overrides tied to bright models.
Matchmaking continues to disallow bright models regardless of this cvar.
Create Server bots now leave their initial observer state and spawn in DM.
Maps still need navigation meshes for bots to navigate normally.

Voting
F1 / F2 default to Yes / No. Existing unrelated bindings are preserved; both
commands are available in Keyboard / Mouse. Vote sounds and animations have
their own settings. Server defaults are in cfg/voting.example.cfg.
Kick votes require three authenticated human players. Team games use teammates;
FFA uses all active humans. Spectators and bots cannot vote. A strict majority
of the original electorate must vote Yes. Leaving does not reduce the threshold.
The caller votes Yes; the target votes No. A ballot lasts 30 seconds, with a
120-second caller cooldown. Listen hosts and configured admins are protected.
Successful kicks block the authenticated Steam identity for five minutes.
Community servers can choose 1-30 minutes; reserved matchmaking uses five.
Ban state is held for the life of the server process, including map changes.

End-of-map voting opens three seconds after the round ends, lasts 20 seconds,
then displays the winner for five seconds before changing maps. Candidates are
up to five unique installed maps from mapcyclefile, excluding the current map.
There is no extension. Ties select randomly among the highest counts. No votes
uses the ordinary mapcycle. Reserved matchmaking servers retain the coordinator's
assigned map and return-to-lobby flow; their player kick votes remain available.

Scoreboard
Hold the scoreboard key, right-click to enable the mouse, then right-click a row.
Actions include Steam profile, separate chat/voice mutes, mute both and kick vote.
Red speaker/chat icons show local mute state; menu checks show which channel is
muted. Mutes are session-local, cleared on disconnect and never written to disk.
Reporting is disabled until the mod receives its own Steam AppID.

Validation
tools/test-vote-rules.cpp exercises the production majority, initial ballot,
Steam/userid/team matching, map tie, timer and ban-limit helpers.
Native Windows checks cover HUD dragging/save, map selection/result/change and
scoreboard mute channels/indicators/disconnect cleanup. A full kick/rejoin test
with three distinct authenticated Steam accounts is still required.
New labels have localization keys; untranslated additions use English fallback.
